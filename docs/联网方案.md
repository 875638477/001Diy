# 自研电源联网方案

手机和电脑要设电压、电流，并读回电压、电流、功率和保护状态。芯片自选，有 PCB 和编程能力。记录里采用的结构是：电源主控负责功率和保护，ESP32 只做网络。两边用 [Modbus 寄存器](modbus-v2.1.md) 说话。手机和电脑不直接碰功率回路。

欣易联原厂模块的结论单独放在 [欣易联模块结论](欣易联模块结论.md)。那条路不再作为实现手段。

## 推荐结构

```
手机浏览器 ──┐
电脑浏览器 ──┼── Wi-Fi ── ESP32 网关 ── UART Modbus RTU ── 电源主控 ── 功率级
电脑 Modbus ─┘              │                              │
                            │                              └─ 硬件过压/过流，不经过 Wi-Fi
                            └─ 本机网页 + HTTP API + Modbus TCP
```

电源主控是 Modbus RTU 从机，地址 `0x01`，115200 8N1。设定值、采样值、保护锁存都在这颗芯片里。ESP32 是 Modbus 主机，同时对局域网提供三种入口，寄存器含义相同：

| 入口 | 谁在用 | 作用 |
|---|---|---|
| 网页 | 手机、电脑 | 日常设置和查看。加到主屏幕后就相当于 App |
| HTTP JSON | 自己以后写的程序 | `GET /api/state` 读取，`POST /api/set` 修改 |
| Modbus TCP 502 | 电脑上的现成主站、Python、组态软件 | 寄存器地址与串口从机一致 |

这样不需要先做原生 App，也不需要自建云。同一台电源上，网页改的电压和 Modbus TCP 改的电压是同一次从机写入。

## 为什么是两颗芯片

功率环、ADC、PWM 和保护放在电源主控（STM32、GD32 或现有控制芯片）。Wi-Fi 收发会带来电流尖峰和不确定的延迟，不适合放在保护路径上。

ESP32 选用 **ESP32-S3-WROOM-1**（或同系列已做好射频的模组），焊在自己的 PCB 上。用模组而不是裸片，是为了天线和认证电路不用自己调；颗粒方案能做，但搜不到网时问题在射频，不在协议。

S3 用片内 USB 下载和打日志，Modbus 可以占用独立 UART。经典 ESP32 的下载口是 UART0（GPIO1/GPIO3），Modbus 就要改到 UART1 或 UART2，避免烧录线和电源串口抢同一个口。ESP8285 能做网关，但 RAM 小，网页、JSON 和 Modbus TCP 堆在一起吃紧，没有必要再选它。

网络断开时输出保持原状态，不因为掉线而突变。掉电再上电默认关闭输出（`S-INI = 0`）。过压、过流、过功率在电源主控和比较器/运放硬件里生效。ESP32 死机或 Wi-Fi 中断时，功率级仍按最后一次有效设定和本地门限运行。

## 手机和电脑分别怎么用

局域网里 ESP32 连上路由器后，用 mDNS 名字 `psu.local`（冲突时改成唯一名字）。页面上同时显示 IP。

手机：系统浏览器打开 `http://psu.local/`。页面上有电压、电流输入，输出开关，以及刷新出来的实测电压、电流、功率、输入电压、恒压/恒流、保护代码。需要图标时用浏览器的“添加到主屏幕”，不必先上架应用商店。

电脑：同一个网址。需要脚本或别的软件时，优先 Modbus TCP，端口 502，从机地址仍是 `0x01`，寄存器表不变。读 `0x0000` 起 19 个寄存器就能覆盖设定值和运行状态。

外网不把 80 和 502 映射到公网。人在外面时用已有的 VPN 或 Tailscale 一类组网，回到家里的局域网再访问。电源参数不适合放在无认证的公网端口上。

第一次配置：ESP32 连不上已保存的路由器时，自己开热点，手机连上后在网页里填写家里的 Wi-Fi。配好后写入 `0x0033`/`0x0034`，面板可以显示 IP。

## 网关里要做的事

1. 连上 Wi-Fi，失败则开配置热点。
2. 每隔约 200 ms 用功能码 `0x03` 读 `0x0000` 起一段运行寄存器。从机若忙，超时后下一轮再读，不要堵死网页。
3. 网页或 Modbus TCP 要改参数时，网关先检查范围，再用 `0x06` 或 `0x10` 写从机。写成功后立刻再读，把读回的值显示出来。
4. 提供下面的 HTTP 接口。数值用物理量，网关负责乘除小数位。

读取：

```http
GET /api/state
```

```json
{
  "v_set": 24.00,
  "i_set": 1.500,
  "v_out": 24.01,
  "i_out": 0.250,
  "power": 6.00,
  "v_in": 48.20,
  "cvcc": "CV",
  "output": false,
  "protect": 0,
  "temp_in": 36.5
}
```

设置电压和电流，单位 V 和 A：

```http
POST /api/set
Content-Type: application/json

{"v_set": 12.00, "i_set": 1.000}
```

开关输出：

```http
POST /api/output
Content-Type: application/json

{"on": true}
```

保护门限走数据组寄存器，不要只写 `0x0000` 就抬高电压。顺序是先写 `S-OVP`（M0 偏移 +3，地址 `0x0053`），再写 `V-SET`。从机发现设定值超过门限时拒绝执行。

网页用同一接口，轮询或用 WebSocket 推送 `/api/state` 均可。先做轮询就能用。

电脑上的最小读取示例（Modbus TCP）：

```python
from pymodbus.client import ModbusTcpClient

client = ModbusTcpClient("psu.local", port=502)
client.connect()
regs = client.read_holding_registers(0x0000, count=4, device_id=1).registers
v_set = regs[0] / 100
i_set = regs[1] / 1000
v_out = regs[2] / 100
i_out = regs[3] / 1000
client.write_register(0x0000, int(round(12.00 * 100)), device_id=1)
client.close()
```

具体的 pymodbus 参数名随版本略有差异，地址和缩放以寄存器文档为准。

固件可以用 Arduino-ESP32，也可以用 ESP-IDF。Modbus 主机和 Modbus TCP 从机可以用 ESP-IDF 的 `esp-modbus`，或 Arduino 侧同时支持 RTU 主机和 TCP 的 Modbus 库。串口日志不要占用 Modbus 那路 UART。

## 电源主控要做的事

实现 [寄存器表](modbus-v2.1.md) 里的从机。至少包括 `0x0000`–`0x0012` 和 M0 的保护门限、`S-INI`。其余寄存器可以后补，未实现的地址返回异常，不要静默写成别的量。

写入 `V-SET`、`I-SET`、保护门限时做范围检查，超限不执行。输出开关和保护逻辑只看本机状态：通信超时不作为关断条件。`PROTECT` 非 0 时禁止打开输出，直到写入 0 清除锁存。

面板若要显示 IP，留出 `0x0030`–`0x0034` 让 ESP32 去写。

开发顺序：

1. 主控从机先用 USB 转串口接到电脑，用 Modbus 主站工具把电压、电流、开关写通。这一步先不要焊 ESP32。
2. ESP32 只做轮询和串口打印，确认缩放和文档一致。
3. 加上网页和 `/api/state`、`/api/set`、`/api/output`。
4. 最后开 Modbus TCP。用手机浏览器和上面的 Python 各改一次电压，确认读回的是同一个从机寄存器。

## PCB

- ESP32-S3-WROOM-1 的天线净空按模组手册留出，下面不要铺铜，也不要靠近 buck 电感和开关节点。
- 模组 3.3 V 由能提供 500 mA 尖峰的电源供电，去耦靠近模组。不要和功率地的大电流环路共用一条细地。
- UART：ESP32 TX 接主控 RX，ESP32 RX 接主控 TX，共地。电平 3.3 V。
- 主控的下载口和 Modbus 口分开。
- 输出默认关。硬件过压、过流不依赖 ESP32 的 GPIO。

## 以后若要独立 App

接口保持 `/api/state` 和 `/api/set` 不变，再用 Flutter 或系统 WebView 包一层即可。不要在 App 里重写一套与 Modbus 表不同的参数定义。电脑侧继续用 Modbus TCP，避免为电脑单独做协议。
