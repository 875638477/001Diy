# 平台选择

自研电源用自己的 PCB 和 ESP32-S3。手机要能设电压、电流并读回状态，人可以在家里、电源在公司。涂鸦和 ThingsCloud 都已有可登录的正规账号。本文记录选型结果和每条路的接法。账号、Token、UUID、AuthKey 只放在本地固件配置里，不写入本仓库。

寄存器和小数位以 [Modbus 寄存器](modbus-v2.1.md) 为准。局域网网页和 502 端口见 [联网方案](联网方案.md)。欣易联原厂固件见 [欣易联模块结论](欣易联模块结论.md)，不再使用。

## 结论

| 顺序 | 做法 | 用来做什么 |
|---|---|---|
| 当前远程方案 | ThingsCloud 账号，官方 ESP32-S3 SDK | 家里用手机设电压、电流、读状态 |
| 同时保留 | 局域网网页 + Modbus TCP 502 | 人在公司、和电源同一路由器时使用 |
| 以后量产再启用 | 涂鸦账号，TuyaOpen | 要进涂鸦智能 / Smart Life 时 |
| 不用云时的替代 | ESPHome + Home Assistant，或自建 ThingsBoard | 不把设定值交给第三方时 |
| 不装进 S3 | Tailscale | 只在需要家里打开原来的网页和 502 时，装在公司的中转电脑上 |

打开输出前，公司现场要先在面板上允许。云端或网页下发的 `output = true` 在允许位未置位时，电源主控拒绝写入 `ONOFF`。过压、过流、过功率只在主控和硬件里执行。

## 为什么先绑 ThingsCloud

ThingsCloud 的 Arduino SDK 列出了 ESP32、ESP32-S2、ESP32-S3、ESP32-C3、ESP32-C6、ESP8266/ESP8285。控制台建一台设备后，固件写入该设备的 MQTT 接入点、Access Token 和 Project Key，板子主动连出。公司路由器不用做端口映射。

电压、电流用属性，小数直接传，不用再套一层整数倍率。手机用 ThingsX，或用控制台生成的界面。ESP32 收到属性后写成电源主控的 Modbus 寄存器，读回的实测值再上报到云。

| 属性 | 方向 | 对应寄存器 | 换算 |
|---|---|---|---|
| `v_set` | 云下发，设备上报 | `0x0000` V-SET | 伏 × 100 |
| `i_set` | 云下发，设备上报 | `0x0001` I-SET | 安 × 1000 |
| `output` | 云下发，设备上报 | `0x0012` ONOFF | 仅在现场允许位有效时写入 0 或 1 |
| `v_out` | 设备上报 | `0x0002` | 原始值 / 100 |
| `i_out` | 设备上报 | `0x0003` | 原始值 / 1000 |
| `power` | 设备上报 | `0x0004` | 原始值 / 100 |
| `v_in` | 设备上报 | `0x0005` | 原始值 / 100 |
| `cvcc` | 设备上报 | `0x0011` | 0 为 CV，1 为 CC |
| `protect` | 设备上报 | `0x0010` | 与寄存器表相同的保护码 |
| `temp_in` | 设备上报 | `0x000D` | 原始值 / 10 |

先写过压门限 `0x0053`，再写 `v_set`。设定值超过门限时从机拒绝。

链接：

- SDK 仓库：<https://github.com/IoT-ThingsCloud/thingscloud-esp-sdk>
- 安装说明：<https://www.thingscloud.xyz/docs/tutorials/connect-device/esp32-arduino-sdk.html>
- 属性下发写法（继电器示例，电源把 `relay` 换成上表属性）：<https://www.thingscloud.xyz/docs/tutorials/connect-device/esp32-arduino-relay-control.html>
- MQTT 主题说明：<https://www.thingscloud.xyz/docs/guide/connect-device/mqtt.html>
- 控制台：<https://console.thingscloud.xyz/>

家里的电脑若要继续用 Modbus Poll 或 pymodbus 直连 502，ThingsCloud 到不了这台设备的 TCP 端口。那种用法走下面的 Tailscale，不和 ThingsCloud 叠在同一条远程链路上。

## 涂鸦账号留到量产

涂鸦账号可以登录，自有 ESP32-S3 也能接入。当前这台先不绑涂鸦，因为多出产品、授权码和面板三步，电源又不是涂鸦的标准品类。

以后要进涂鸦智能 / Smart Life 时：

1. 用 TuyaOpen。开发主机支持表包含 ESP32-S3。SDK：<https://tuyaopen.ai/zh/>。平台说明：<https://tuyaopen.ai/zh/docs/about-tuyaopen>。
2. 在涂鸦开发者平台创建产品，拿到 `PID`。步骤：<https://tuyaopen.ai/zh/docs/cloud/tuya-cloud/creating-new-product>。
3. 每块板配置 `TUYA_PRODUCT_ID`、`TUYA_OPENSDK_UUID`、`TUYA_OPENSDK_AUTHKEY`。开发阶段的 UUID 和 AuthKey 向涂鸦技术支持领取，不写进仓库。
4. 功能定义成 DP。数值型 DP 是整数，小数用倍率：电压倍率 2（0.01 V），电流倍率 3（0.001 A），与寄存器缩放一致。DP 模型：<https://developer.tuya.com/cn/docs/iot-device-dev/TuyaOS-iot_abi_dp_ctrl?id=Kcoglhn5r7ajr>。
5. 固件收到 DP 后同样写 Modbus。现场允许位规则与 ThingsCloud 相同。

标准插座面板没有电压、电流设定。电源要单独做面板，所以第一台不走这条。

## 开源平台

涂鸦、ThingsCloud、欣易联的云都不能自己部署。不想把设定值交到这些账号上时，用开源方案，ESP32-S3 都能接。

| 平台 | 链接 | 适合的情况 |
|---|---|---|
| ESPHome + Home Assistant | <https://esphome.io/> ，<https://www.home-assistant.io/> | 这一台电源的网页和手机 App。ESPHome 做串口 Modbus，Home Assistant 出界面 |
| Modbus TCP 桥 | <https://github.com/rosenrot00/esphome_modbus_bridge> | 电脑上的主站软件仍要连 502 |
| ThingsBoard 社区版 | <https://github.com/thingsboard/thingsboard> | 要自己一台服务器，形态接近涂鸦：设备属性、仪表盘、一批设备 |
| ESP32-S3 接入 ThingsBoard 的示例 | <https://github.com/MilladAnsari/esp32s3-thingsboard-mqtts-onboarding> | MQTTS、设备领取和自动开通。示例上报的是温湿度，电源改成上表那些属性 |

Home Assistant 放在公司那台常开的电脑上。人在家里时，用 [远程操作](远程操作.md) 里的 Tailscale 访问它，不把 Home Assistant 端口映射到公网。

## Tailscale 不装进 ESP32-S3

Tailscale 官方客户端没有 ESP32 版本。它解决的是另一件事：家里要打开公司局域网里原来的网页和 Modbus TCP。中转软件装在公司的电脑或树莓派上，只公布电源这一台的 IP。细节、社区固件链接和现场约束都在 [远程操作](远程操作.md)。

当前远程手机操作走 ThingsCloud，不把 Tailscale 和 ThingsCloud 配成两条同时要用的远程通道。
